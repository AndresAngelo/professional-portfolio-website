# Stage 2: Spec-Driven Development (Kiro)

## Purpose

Stage 2 leverages Kiro IDE, combining **Qwen Coder Next** (for structural planning and dependency ordering) and **Claude Haiku** (for high-fidelity spec generation). It transforms Stage 1's `master-files/` into a granular, highly structured 3-layer hierarchy designed for spec-driven automation.

## 3-Layer Task Hierarchy (~1,000 Tasks Total)

The project scope is structured into a deterministic 10 × 10 × 10 execution model:

- **Layer 1: Milestones (~10 Milestones)** — High-level project phases (e.g., M1: Core Infra, M2: Content Architecture, ..., M10: Release Prep).
- **Layer 2: Goals (~10 Goals per Milestone)** — Feature modules and subsystem objectives (e.g., G1: Schema Infrastructure, G2: Enum Schemas).
- **Layer 3: Tasks (~10 Tasks per Goal)** — Atomic, dependency-ordered execution units with concrete target files and verification commands.

Total Pipeline Scope: ~1,000 actionable, spec-verified tasks (scaled up or down depending on project complexity).

## Model Allocation Strategy

- **Qwen Coder Next** (0.05 credit multiplier): Used for structural task parsing, milestone dependency mapping, and sequence alignment.
- **Claude Haiku**: Used for generating complete EARS requirements, architectural specs (`design.md`), and the goals-skeleton `tasks.md`.

## Outputs per Milestone

For each milestone M[N], Kiro generates **three spec files**:

```
.kiro/specs/M[N]-[kebab-name]/
├── requirements.md   — EARS-formatted requirements (full detail)
├── design.md         — Technical architecture, correctness properties, testing strategy
└── tasks.md          — 10-goals skeleton + Stage 3 delegation instructions (see below)
```

> **Note:** Individual goal files (`goal1.md`–`goal10.md`) are **not** authored in Kiro.  
> They are generated by Stage 3 (Google AI Studio) to avoid hitting Kiro's file size limits.

---

## tasks.md Structure & Responsibilities

Kiro's `tasks.md` is deliberately lightweight. It contains:

1. **Front matter** — milestone name, workflow status, total task count, requirements coverage.
2. **Overview** — stateless execution principles, task format contract, dependency notes.
3. **Task Dependency Graph** — JSON wave schedule for all 100 tasks across 10 goals.
4. **10 Goal Skeleton Sections** — one `### M[N].G[X]: <GoalName>` block per goal, each with:
   - Goal objective
   - Goal success criteria (bullet list)
   - Stub task list (`M[N].G[X].T1` – `M[N].G[X].T10`) with titles only
   - Status marker (`NOT STARTED`)

5. **Stage 3 Delegation Block** (bottom of file) — explicit instruction to Google AI Studio:

```markdown
## Stage 3 Delegation Instructions

**Audience:** Google AI Studio (Stage 3 agent)

For each goal G1–G10 in this file, generate a separate goal file:
- **File naming:** `goal1.md`, `goal2.md`, ..., `goal10.md`
- **Output location:** `.kiro/specs/M[N]-[kebab-name]/`
- **Each goal file must contain ~10 fully-detailed atomic tasks** following the
  task format contract below.

### Task Format Contract (per task in each goal file)

Every task MUST include all of the following sections:

| Section | Requirement |
| :--- | :--- |
| **Title** | `M[N].G[X].T[Y]: <Action-Oriented Name>` |
| **Objective** | One sentence: what this task accomplishes |
| **Acceptance Criteria** | 4–8 bullet points, observable and testable |
| **Prerequisites** | Full file paths, installed deps, state assumptions — no "see previous task" |
| **Implementation Details** | Step-by-step instructions with actual TypeScript/shell code |
| **Validation** | Exact commands + expected output to confirm completion |
| **Satisfies Requirements** | Requirement numbers from `requirements.md` (e.g., `Req 5.1, 5.2`) |

### Constraints

- Tasks must be **fully self-contained** — a stateless LLM with no conversation
  history must be able to execute each task from the task text alone.
- No placeholder text, no "TBD", no "see design.md" references without quoting
  the relevant excerpt inline.
- Each task should be completable in **one stateless orchestrator turn**
  (Bonsai 2 27B CoT pass → Gemma-4-12B code execution pass).
```

## Stage 2 → Stage 3 Handoff Checklist

Before handing off to Stage 3, confirm all of the following for every milestone:

- [ ] `requirements.md` complete and EARS-formatted
- [ ] `design.md` complete with all required sections (Overview, Architecture, Components and Interfaces, Data Models, Correctness Properties, Error Handling, Testing Strategy)
- [ ] `tasks.md` passes Kiro spec format validation (no errors)
- [ ] `tasks.md` Task Dependency Graph JSON is present and accurate
- [ ] `tasks.md` Stage 3 Delegation Block is present at the bottom of the file
- [ ] User has approved all three spec files before Stage 3 begins

---

## Review Gate

**Gate 1 (end of Stage 2):** User reviews and approves all `requirements.md`, `design.md`, and `tasks.md` files across all milestones before Stage 3 (Google AI Studio) begins goal file generation and scaffolding.
