## Notes

### Cross-Goal Notes

- **Single client island:** `mobile-nav-toggle.tsx` is the only `'use client'` module in M4. All matching, derivation, reducer, and contact logic lives in directive-free modules (G2) that both server and client code import.
- **Derived Contact entry:** The Contact nav entry is derived by `buildNavEntries` and is never stored in `content/site.json`. It links to `#contact` and is never current.
- **Shared renderability check:** `getRenderableChannels` is the single source of truth for the nav Contact entry, header action, footer `#contact` region, and `ContactLinks`, so they cannot disagree.
- **One `main`:** Only `layout.tsx` renders `main`. `not-found.tsx` renders a `section` inside it.
- **Scope guard:** M4 edits only `src/app/`, `src/components/layout/`, and `tests/`. Missing primitives, tokens, or dependencies are recorded in `task-notes.md` and escalated (`AGENTS.md` 6.2), never patched.
- **Deferred verification:** Req 11.5 (`notFound()` from invalid slugs) is confirmed only after M6–M8 routes exist; M4 verifies the boundary renders through unit and build checks.

### Testing Patterns

- Property tests use `fast-check` (no hand-rolled generators), at least 100 iterations each, and a tag comment: `Feature: m4-global-layout-navigation, Property N: <text>`.
- Property-to-file mapping: P1–P2 `current-route.test.ts`; P3–P4 `nav-entries.test.ts`; P5 `disclosure.test.ts`; P6 `mobile-nav-toggle.test.tsx`; P7 `contact-channels.test.ts`; P8 `contact-links.test.tsx`; P9–P10 `site-footer.test.tsx` (P10 also `contact-links.test.tsx`); P11 `site-header.test.tsx`; P12–P13 `site-metadata.test.ts`; P14 `not-found.test.tsx`.
- Render-based property tests call `cleanup()` between iterations and use bounded array sizes.
- `next/navigation` is mocked with `vi.mock` for `usePathname`; `getSiteConfig` is mocked with fixtures from `tests/fixtures/site-config.ts`. Footer tests inject `year`.
- Enter and Space tests use `@testing-library/user-event` (Approved 2026-10-22 (approval 1a); pin exact version and document purpose/maintenance status before adding); jsdom does not convert `keydown` to `click`.
- jsdom does not evaluate Tailwind; CSS hiding, contrast, and layout are covered by the manual verification list.
