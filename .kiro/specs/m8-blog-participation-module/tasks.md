## Overview

This file defines the 10-goals skeleton for M8. Individual task detail (~10 tasks per goal) is generated by Stage 3 (Google AI Studio) into separate `goal1.md`–`goal10.md` files in this directory.

Each task in the generated goal files must be fully self-contained for stateless orchestrator execution (Bonsai 2 27B CoT → Gemma-4-12B code execution). No inter-task conversation history is assumed.

M8 delivers the Blog / Participation module: the index route `/blog` (`SCR-05`), the detail route `/blog/[slug]` (`SCR-06`), ten components in `src/components/blog/` (nine presentational plus one client island, `BlogExplorer`), and pure helpers in `src/lib/blog/` for tag keys, ordering, tag option derivation, filter parsing and merging, filtering, adjacent post selection, card data, result-count text, and metadata. M8 composes M2 loaders, M3 primitives, the M4 shell, the M5 `formatDisplayDate` and `compareStrings`, and the M6 `demoteHeadings` (Decision 3 rule) without modifying them. `BlogExplorer` is the only `'use client'` module and the only caller of `useSearchParams`. M8 emits no JSON-LD and no RSS output.

## Notes

### Cross-Goal Notes

- **One client island:** `BlogExplorer` is the only `'use client'` module and the only `useSearchParams` caller. All other components are plain; `BlogFilterBar`, `BlogPostList`, and `BlogPostCard` join the client bundle only as the Explorer's children. A `FilterChip` wrapper with its own directive is allowed only if M3 `FilterChip` is not already a client component, and is recorded in `task-notes.md`.
- **URL is the filter state:** The Explorer derives filters from `useSearchParams()` each render and writes with `router.replace(..., { scroll: false })`. No duplicate state. Only `useRouter` and `useSearchParams` are mocked in tests.
- **Static HTML is complete:** The `Suspense` fallback is the unfiltered `BlogPostList`, so `/blog` contains every published card without JavaScript. The filter bar appears only after hydration.
- **Serializable client props:** The Explorer receives `BlogCardData` and `TagOption[]` only. `content` and `draft` never cross to the client.
- **One tag key:** `tagKey` (trim, `toLowerCase`) is the single comparison used for deduplication, parsing, filtering, and sorting.
- **One encoding path:** `serializeBlogFilters` is defined as `mergeBlogFilterParams('', f)`.
- **Adjacency direction:** `previous` is the next older post and `next` is the next newer post (Decision 1).
- **Draft defense in depth:** M2 loaders, then helpers (`deriveTagOptions`, `filterBlogPosts`, `selectAdjacentPosts`), then `BlogPostList`, each drop drafts.
- **Heading demotion (Decision 3):** G1.T8 decides once. Case 1 imports the M6 helper read-only. Case 2 creates `src/lib/blog/demote-headings.ts` in G7.T1. The M7 `shiftHeadings` helper is never imported.
- **Reuse, do not recreate:** `formatDisplayDate` and `compareStrings` come from M5. If either is missing, G1.T6 stops and escalates; M8 writes nothing outside its four locations.
- **Scope guard:** M8 edits only `src/app/blog/`, `src/components/blog/`, `src/lib/blog/`, and `tests/`. Missing primitives, tokens, or dependencies are recorded in `task-notes.md` and escalated (`AGENTS.md` 6.2), never patched.
- **Deferred verification:** Layout, overflow, touch targets, contrast, and layout shift are not evaluated by jsdom and are covered by the manual list (layout shift measurement and JSON-LD are M9).
- **Empty filtered state:** Unreachable through the URL in production (Decision 12); tested by passing a `tagOptions` entry that no card has.

### Testing Patterns

- Property tests use `fast-check` (no hand-rolled generators), at least 100 runs each, and a tag comment: `Feature: m8-blog-participation-module, Property N: <text>`.
- Render-based property tests call `cleanup()` between iterations and use bounded array sizes.
- Explorer tests use the store-backed `next/navigation` mock in `tests/blog/helpers/navigation-mock.ts`; `replace` writes into the store so `useSearchParams` reflects it.
- Loaders are mocked with `vi.mock` using fixtures from `tests/blog/helpers/blog-fixtures.ts`.
- Date tests set `process.env.TZ` per case; purity tests use deeply frozen inputs.
- jsdom does not evaluate Tailwind; CSS layout, overflow, touch targets, and contrast are covered by the manual verification list.
