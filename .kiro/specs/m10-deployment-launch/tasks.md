## Overview

This file defines the 10-goals skeleton for M10. Individual task detail (~10 tasks per goal) is generated by Stage 3 (Google AI Studio) into separate `goal1.md`–`goal10.md` files in this directory.

Each task in the generated goal files must be fully self-contained for stateless orchestrator execution (Bonsai 2 27B CoT → Gemma-4-12B code execution). No inter-task conversation history is assumed.

M10 is the launch layer, not a product module. It delivers two small offline-testable tools under `scripts/launch/` (`csp-hashes.ts` and `verify-deployment.ts`, with shared pure code in `scripts/launch/lib/`), their tests and fixtures in `tests/launch/`, a version-controlled `vercel.json` (security headers and cache rules only), the seven operations documents in `docs/operations/`, `CHANGELOG.md`, README updates, and an optional `.github/workflows/verify.yml`. Most M10 work is human-performed (Vercel dashboard, DNS, preview and production deployment, tagging, sign-off). Those tasks are marked **HUMAN**, name who performs them, and name the Evidence_Record they fill. The tools import the M9 types, report helpers, and build-layout reader read-only (`resolveBuildLayout` is always called with a literal `{}` env). Every pure decision function (CSP builders, config validators, header and page checks, argument parsing, report builder, docs lint, check-in dates) carries a fast-check property; I/O shells stay thin and are tested with a fake `Fetcher`.

Eight Approval_Items (A1–A8, `design.md`) were decided by the human on 2026-10-22: A1 `vercel.json` Approved (approval A1); A2 and A4 npm scripts Approved; A3 `package.json` version Declined; A5 `next.config.ts` pre-approved only if the one-line static-export verification fails; A6 CI workflow Approved; A7 tag `v1.0.0` and merge to production Manual, at launch (approval requested at launch time); A8 `.gitignore` `reports/` Approved. All devDependencies are approved (approval 1a) and pinned to exact versions at implementation. G1 records these decisions in `task-notes.md`. Each gated task begins with a check of the recorded decision. M10 does not touch `src/`, existing files under `tests/` or `scripts/audit/`, `.kiro/specs/m10-deployment-launch/.config.kiro`, or add any dependency, analytics, API route, environment variable, or P1 scaffolding. The only content change is the `content/site.json` values (`siteUrl` and real contact data), made by the owner.
