## Overview

This file defines the 10-goals skeleton for M9. Individual task detail (~10 tasks per goal) is generated by Stage 3 (Google AI Studio) into separate `goal1.md`–`goal10.md` files in this directory.

Each task in the generated goal files must be fully self-contained for stateless orchestrator execution (Bonsai 2 27B CoT → Gemma-4-12B code execution). No inter-task conversation history is assumed.

M9 is a verification layer, not a product module. It delivers offline command-line audits under `scripts/audit/` (with shared code in `scripts/audit/lib/`) that read the statically built site (Build_Output) and validated content, write JSON Audit_Reports to the git-ignored `reports/` directory, and exit non-zero on a Quality_Gate failure. The audits are: route inventory, built-HTML structure and hygiene, internal link crawler, SEO and metadata, axe-core accessibility, performance budgets with a committed `baselines/performance.json`, external link inventory (plus the manual `audit:links:online`), and Lighthouse (approval-gated). M9 also delivers pure JSON-LD builders in `src/lib/structured-data/`, a server component `src/components/structured-data/json-ld.tsx`, Content_Gate suites in `tests/audit/content/`, and four documents in `docs/quality/`. Every pure decision function (checkers, comparators, builders, report helpers) carries a fast-check property; I/O shells stay thin.

Six Approval_Items (A1–A6, `AGENTS.md` 6.2) gate changes to `package.json`, the lockfile, `.gitignore`, and the M5, M6, and M8 page modules. All six were Approved 2026-10-22 (approvals A1-A6); G1 records the approvals in `task-notes.md`. Each gated task begins with a check that the approval is recorded, and fallbacks remain only as short historical notes. Exact dependency versions are pinned at implementation time after documenting purpose and maintenance status. M9 does not touch `next.config.ts`, `tsconfig.json`, CI config, or `.kiro/specs/m9-quality-accessibility-performance/.config.kiro`, and contains no M10 scope.

- **No quiet exemptions:** A rule is skipped only through a named, reported mechanism (`APPROVALS` switch or `DISABLED_AXE_RULES`). Never disable a rule to make a page pass.

- **Exit codes (Decision 10):** 0 pass, 1 at least one `error` finding, 2 environment or usage error. The aggregate returns 1 over 2.
- **Decisions needing human confirmation (G1.T9):** Decision 8 (not-found page is exempt from canonical, Open Graph, and the `noindex` prohibition, and must carry `noindex`), the Decision 7 reading of the bare marker words in Req 5.5 as host and call forms, and the Vercel Hobby limits re-check for the 25 MB budget.

### Testing Patterns

- Property tests use `fast-check` (no hand-rolled generators), at least 100 runs each, and a tag comment: `Feature: m9-quality-accessibility-performance, Property N: <text>`.
- Audit tests load static HTML fixture trees through `AUDIT_BUILD_DIR`; no test runs a build or opens a socket except `static-server.test.ts` on `127.0.0.1` with an ephemeral port.
- Content gate tests use `fs.mkdtemp` temp trees, `vi.spyOn(process, 'cwd')`, `vi.resetModules()`, and dynamic imports; they never write under `content/`.
- Document tests read the committed Markdown files and assert required headings, commands, and names.
- Audit CLIs run with `vite-node --config vitest.config.ts scripts/audit/<name>.ts` (Decision 3); on Windows PowerShell pass extra arguments after `--`.
