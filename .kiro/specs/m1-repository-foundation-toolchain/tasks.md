### Task Format Contract

Every task in each goal file MUST include:

| Section | Requirement |
| :--- | :--- |
| **Title** | `M1.G[X].T[Y]: <Action-Oriented Name>` |
| **Objective** | One sentence describing what the task accomplishes |
| **Acceptance Criteria** | 4–8 bullet points, observable and testable |
| **Prerequisites** | Full file paths, installed deps, state assumptions — no "see previous task" |
| **Implementation Details** | Step-by-step instructions with actual shell/TypeScript/JSON code |
| **Validation** | Exact commands + expected output to confirm completion |
| **Satisfies Requirements** | Requirement numbers from `requirements.md` |

### Constraints

- Tasks must be **fully self-contained** — a stateless LLM with zero conversation history executes each task from the task text alone.
- No placeholder text, no "TBD", no bare file references without quoting the relevant excerpt inline.
- Each task completable in **one stateless orchestrator turn** (Bonsai 2 27B CoT → Gemma-4-12B code execution).
- Windows PowerShell syntax for all shell commands.
- All file paths relative to workspace root: `c:\dev\andres-webapp-professional\personal-website-portfolio\personal-website-portfolio-v2\`.
